# 忌口档案（跨会话持久）

忌口是**所有模式的第零步**：任何推荐、转盘、下单之前，先加载用户忌口档案，并把结果应用到过滤中。

档案保存在 `~/.workbuddy/mcd-profile.json`，重新登录、换会话、换工作区后依然有效。

## 两个等级

| 等级 | 取值 | 处理方式 | 用户话术 |
|---|---|---|---|
| **绝对不吃** | `strict` | **硬排除**：任何模式、任何方案、转盘候选池都不得出现 | 「不吃」「绝对不碰」「过敏」「讨厌」 |
| **勉强接受** | `reluctant` | **不排除，但降权**：排序排到后面，转盘大幅降低中签率，输出时必须标注 | 「还行」「不太爱」「实在没有也行」 |

关键词同时匹配**餐品名称**和菜单 `tags`。

## 首次使用：先问，再做事

档案不存在或为空时，**先问忌口再执行任何功能**：

> 先确认一下：有没有绝对不吃的东西？比如过敏、忌辣、不吃牛肉？（没有的话回「没有」，我就不问了）

规则：

- 用户说「没有」「随便」→ 记下「无忌口」，本会话不再追问，也不要每次都问。
- 用户给了忌口 → 立即写入档案，并复述确认。
- 用户没回答就要求推荐 → 可以推荐，但**默认不设置任何忌口**，并在回复末尾提示「如果有忌口可以告诉我，我会记住」。

档案已有内容时**不再重复询问**，直接应用；用户主动说「加个忌口」「我不吃 X 了」时才更新。

## 常去门店记忆（同一个档案，跨会话）

门店定位最大的摩擦是反复问「城市 + 地标」。把用户确认过的常去门店也记进 `mcd-profile.json`，下次直接复用：

```bash
# 记住常去门店（storeCode 来自 query-nearby-stores）
python scripts/profile.py store set --code 1420450 --name "深圳福田站餐厅" --landmark "深圳·福田" --pickup "到店自取"

# 查看已记住的门店
python scripts/profile.py store show

# 清除（换城市或记忆有误时）
python scripts/profile.py store clear
```

规则：
- `pickup` 是「上次取餐方式」**提示**，不是强制；用户这次想换仍按本次意愿。
- `landmark` 用「城市·地标」格式，便于展示与快速定位。
- 记忆为空才走 SKILL.md 的「三级兜底」定位；已有记忆就直接拿 storeCode 查菜单/算价。

## 脚本用法

```bash
# 查看忌口
python scripts/profile.py show

# 新增（--keywords 缺省用名称；--allergy 标记为过敏）
python scripts/profile.py add --name 花生 --level strict --keywords 花生,坚果 --allergy
python scripts/profile.py add --name 辣 --level reluctant --keywords 辣

# 删除
python scripts/profile.py remove --name 辣

# 输出给其他脚本的过滤参数
python scripts/profile.py effective
```

`effective` 返回 `strict`（硬排除关键词）、`reluctant`（勉强接受关键词）、`allergies`（过敏项）。

## 各模式如何应用

取到 `effective` 结果后：

- `strict` → 传进 `combo_optimizer.py` 的 `exclude_keywords`，或 `spin_wheel.py` 的 `exclude_keywords`。**绝对不吃的餐品连候选池都进不去**。
- `reluctant` → 传进 `soft_exclude_keywords`：
  - 凑单/配餐：方案仍可包含，但**排序排到无勉强项的方案之后**，并在输出里标注 `reluctant_matches`。
  - 转盘：中签权重降到 15%，且抽中时标注。

输出时必须显式说明，例如：

> 这份含「辣」（你标记为勉强接受），如果想完全避开可以换备选方案。

## 推荐结果反馈与长期偏好（授权后才保存）

用户对推荐结果可以给出轻量反馈。反馈分两类，**保存规则完全不同**：

### 本次反馈（默认不保存）

可选反馈：太贵 / 份量不足 / 不喜欢该品类 / 想更健康 / 想更丰富 / 下次记住。

- 反馈只作用于**当前这一轮**的方案调整：重新生成、重排序或换备选。
- **一次性反馈不自动写入长期档案**，会话结束即失效。
- 「想更健康」→ 当前轮切到 lean 目标；「想更丰富」→ 切到 rich 目标；「太贵」→ 重跑 cheap 目标并说明差价。

### 长期偏好（必须用户明确授权）

只有用户明确表达保存意图时才写入档案，例如「以后都按这个来」「记住我不爱喝可乐」「以后默认省钱优先」：

1. **先复述要保存的内容**，让用户确认（保存什么、影响范围）。
2. 用户确认后才写入，写入后告知「已记住，可随时说『忘掉』清除」。
3. 长期偏好区分为：目标偏好（rich/cheap/lean 默认）、品类偏好（不喜欢某品类）、预算习惯。
4. 用户说「忘掉 XX」「清除偏好」时立即删除对应条目，不追问理由。

### 授权边界（不可妥协）

- **不得把一次性反馈推断为长期偏好**：用户这次说「太贵」不等于以后永远低价优先。
- **不得自动推断用户关系或他人信息**：不保存「家人」「同事」「小朋友」等角色及其偏好，除非用户自己明确提交并确认。
- 长期偏好与忌口档案分开存放，清除长期偏好不影响忌口硬约束。
- 用户要求查看已存偏好时，原样展示，不加工不美化。

## 过敏：关键词过滤不可靠

菜名匹配**无法覆盖配料与交叉接触**（例如「脆薯饼」不含花生字样但可能共用油锅）。

- 档案里标了 `--allergy` 的项，除硬排除外，还要提示用户向门店核实。
- **不得因为关键词没匹配上就宣称「不含过敏原，可以放心吃」**。
- 严重过敏时，宁可推荐成分最简单的餐品，也不要打包票。

## 注意

- 忌口是硬约束，优先级高于「丰富优先」「低价优先」等优化目标，**也高于转盘的随机性**——抽中绝对不吃的必须重抽。
- 用户更新忌口后，当前会话正在进行的推荐要重新过滤，不能沿用旧结果。
- 档案只记录关键词，不记录具体餐品编码（菜单会变，编码会失效）。
