# mcd-smart-order · 麦当劳智能点单助手

> 一句话：对着 AI 说「两个人 60 块以内，不吃辣，帮我凑一单麦当劳」，它基于麦当劳 MCP 的实时门店、菜单、优惠券与算价数据，给出可对比的方案、算清真实应付，并在你明确授权后完成下单。

**参赛项目**：麦当劳程序员节创意开发大赛
**开发平台**：WorkBuddy（Skill 形态，v1.1.0）
**数据来源**：麦当劳 MCP Server（实时接口，零静态菜单）

---

## 1. 项目介绍

mcd-smart-order 是一个运行在 WorkBuddy 平台上的智能体技能（Skill）。它把「点麦当劳」这件事拆成三个问题——**选什么、多少钱、怎么下单**——并用麦当劳 MCP 的真实数据逐段回答：

- **选什么**：按预算 / 人数 / 忌口 / 热量 / 口味，从当前门店真实在售菜单里组合餐品，支持「丰富 / 省钱 / 健康」三套目标同屏对比；
- **多少钱**：每个候选方案都调用 `calculate-price` 拿真实实付（区分「菜单预估价」「活动宣传价」「券面额」「实付」四种口径，杜绝用预估价冒充最终价）；
- **怎么下单**：到店自取 / 得来速 / 麦乐送 / 企业团餐四种场景，经过「确认卡 → 二次算价 → 幂等下单」安全门禁后才创建订单，未支付前可取消。

### 六大能力

| # | 能力 | 解决什么问题 |
|---|---|---|
| 1 | 省钱凑单 | 「30 块钱一个人吃」「怎么凑最划算」——预算内组合优化，无解时告诉你「还差多少」 |
| 2 | 营养配餐 | 「600 大卡以内配一餐」「不吃辣」——按热量 / 蛋白质 / 忌口搭配，数据缺失标「未核实」 |
| 3 | 门店点单 | 「附近麦当劳，外送」——四种履约场景完整下单闭环 |
| 4 | 订单与资产 | 「我的券 / 积分 / 上次那单」——历史订单一键复购、订单异常自助处理 |
| 5 | 单品套餐转盘 | 「不知道吃什么，随便抽一个」——符合条件餐品随机抽取，诚实标注「随机」 |
| 6 | 多人点餐与 AA | 「三个人一起点，AA」——多人偏好组合 + 按实付均摊 |

### 设计取舍（为什么是 Skill 而不是小程序 / 网页）

- **复用自然语言输入**：用户不用学新界面，一句话说清多重约束（预算 + 人数 + 忌口 + 场景）；
- **无需前端部署**：逻辑全部在提示词契约 + 离线脚本 + MCP 实时数据三层，装好即用；
- **保留完整交易闭环**：MCP 提供真实门店 / 菜单 / 算价 / 下单能力，不是模拟数据。

## 2. 安装方法

### 方式 A：安装为 WorkBuddy 用户级 Skill（推荐）

把 `mcd-smart-order/` 整个目录复制到用户技能目录：

```bash
# Windows（Git Bash）
cp -r ./mcd-smart-order ~/.workbuddy/skills/

# macOS / Linux
cp -r ./mcd-smart-order ~/.workbuddy/skills/
```

安装后重启 WorkBuddy 会话即可生效。技能只在检测到**点单意图**时自动加载（触发词与排除规则见 `mcd-smart-order/SKILL.md` 的 description）。

### 方式 B：安装为项目级 Skill

把目录复制到某个项目的 `.workbuddy/skills/` 下，仅该项目可用：

```bash
cp -r ./mcd-smart-order <你的项目目录>/.workbuddy/skills/
```

### 前置条件

1. WorkBuddy 客户端已配置**麦当劳 MCP Server**（提供 `query-meals`、`calculate-price`、`create-order` 等工具）；
2. Python 3.10+（仅离线脚本与测试需要，技能主流程不依赖）。

### 验证安装

```bash
cd mcd-smart-order/scripts
python run_tests.py            # 离线回归：10 个套件 162 项，约 100 秒
python run_tests.py --check-sync  # 核对源目录与安装目录是否一致
```

## 3. 使用示例

安装后在 WorkBuddy 对话中直接用自然语言触发，无需命令。

### 示例 1：省钱凑单（默认「丰富优先」）

> **用户**：帮我凑个 30 块钱的麦当劳，一个人吃

技能行为：查当前门店实时菜单 → 离线脚本枚举组合 → 三选一视图（主推·丰富 / 省钱·低价 / 健康）→ 对每个候选调 `calculate-price` 拿实付 → 展示对比与「为什么选它」。

### 示例 2：营养配餐

> **用户**：600 大卡以内配一餐，要有肉

技能行为：`list-nutrition-foods` 取营养成分（160 条，按行解析）→ 与门店菜单容错匹配（实测约 17% 可精确核实）→ 不可核实项明确标注「未核实」，不估算、不宣称达标。

### 示例 3：多人点餐 + AA

> **用户**：三个人一起点，一共 120 以内，有一个不吃牛肉，AA

技能行为：联合解析全部硬约束（人数 / 预算 / 忌口）→ 每人一份主食 + 公共分享餐（不重复计费）→ `calculate-price` 逐项小计 → 按每人实际所选金额均摊。

### 示例 4：完整下单闭环

> **用户**：就要这个，下单吧

技能行为（安全门禁，缺一不可）：
1. 展示「下单前确认卡」：门店 / 履约方式 / 商品清单 / 券 / 费用 / 实付 + 不可逆提示；
2. 单独询问「是否确认创建订单？」——「确认」「就要这个」只算选餐确认，不算下单授权；
3. 用户明确授权后，`create-order` 前再次 `calculate-price` 校验（二次实付必须一致）；
4. 携带幂等键 `idemKey` 创建订单 → 引导支付 → 支付状态以 `query-order` 为准。

### 示例 5：历史订单复购

> **用户**：上次那单再来一次

技能行为：`order-list` 取历史订单 → `reorder.py` 对照当前门店菜单（分出在售 / 已下架 / 涨价）→ 重新 `calculate-price` → 获得授权后才下单。

更多触发词与模式路由见 `mcd-smart-order/SKILL.md`；MCP 调用规范见 `mcd-smart-order/references/ordering-core.md`。

## 4. 目标用户

| 用户群 | 典型场景 |
|---|---|
| 价格敏感型顾客 | 「怎么凑最划算」「券怎么用最省」——券后真实算价，只认实付 |
| 健康 / 减脂人群 | 「600 大卡以内」「低蛋白高纤维」——营养数据说话，未核实就明说 |
| 选择困难症患者 | 「不知道吃什么」——转盘随机抽，不假装「精选」 |
| 团体 / 团队组织者 | 下午茶团购、AA 聚餐——多人偏好一次满足，金额按实付分摊 |
| 高频复购用户 | 「老样子再来一单」——历史订单 × 当前在售对照，涨价下架提前告知 |

## 6. 质量与安全

- **离线回归**：10 个测试套件共 **162 项检查全部通过**（约 100 秒可一键复跑，命令见第 2 节）；
- **真实接口验证**：在麦当劳深圳福田高铁站餐厅（`storeCode 1420450`）完成只读取数、算价核对与「创建 → 查询 → 取消」下单闭环（测试单已取消，未支付），证据见 `TEST_REPORT.md`；
- **交易安全**：写操作受冻结契约约束——先算价后下单、两步确认（选餐 ≠ 授权）、幂等键防重复下单、下单前二次算价、异常先查后做、审计脱敏；
- **口径诚实**：菜单预估价 / 活动宣传价 / 券面额 / 实付四种价格严格分层，只有 `calculate-price` 的返回值可称「实付」。

详细集成说明（MCP Server、工具清单、调用流程、业务价值）见 **[MCP_INTEGRATION.md](MCP_INTEGRATION.md)**。
